# Writing for WatchRead

Write for someone trying to read a lesson or finish a task. Say what a control does and what to do when something fails. Describe the useful behavior instead of praising the product.

Use straight quotes, sentence-case headings, and ordinary punctuation. Avoid decorative bold, emoji, generic promises, and claims the evidence cannot support. Keep model names, measurements, and limitations accurate.

The prose-humanizer pass covered the interface, README, presentation script, demo notes, deployment guide, and Fable 5.1 credits. Original transcripts, model responses, provenance, and historical prompts remain unchanged. Their wording is part of the evidence, not a style template for new copy.

Run `npm run copy:check` before publishing. The production build runs it automatically. Tests feed each of its five rules a failing example. The check catches a small set of style patterns; an editor must still check meaning, rhythm, and facts.
